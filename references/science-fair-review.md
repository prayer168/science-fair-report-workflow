# 科展作品書逐章整合與完整性檢查

以使用者原作品書與當次明確修改為準。以下是章節職責與檢查方法，不代表特定年度競賽的全部官方規定。實際章名、括號中的學生分工、編號層級與頁面樣式從當次原檔取得；保留使用者要求的格式。

## 逐章檢查

| 原書章節範例 | 自行整合與檢查內容 |
|---|---|
| 封面／題目 | 題目、副標題、年屆與全書稱呼一致；姓名等由實際原檔保留，不推測。 |
| 摘要 | 交代問題、研究目的、主要方法與已有發現；尚未實驗時寫成研究設計摘要，不能把預期目標寫成結果。修改研究範圍後同步更新。 |
| 壹、前言（含研究動機、目的、文獻回顧） | 動機通往可回答問題；研究目的與保留的子實驗對應；已刪除的研究階段不再以現行任務出現。文獻回顧有對應引用，假說與既有證據分開。 |
| 貳、研究設備及器材 | 器材名稱、數量、尺寸／量程／精度等規格足以準備；與各實驗用量及圖示一致。區分共用設備、獨立樣本、重複量測、耗材、備品，不把同一裝置每次測試計為多台。 |
| 參、研究過程或方法 | 架構圖含題目、目的、目前各階段與子實驗；步驟可照做，有操作／控制／應變變因、對照、重複、觀察時間、成功失敗定義與資料分析方式。詳細圖直接嵌入，標註設備、數量、規格與重要位置；接線、尺寸、樣本數和正文相同。 |
| 肆、研究結果 | 各實驗有對應可編輯紀錄表、單位與試次／樣本 ID；結果圖表須依實際紀錄產生。空表與分析欄可先備妥，但註明待實測；不能從方法或參考文獻編造本研究結果。 |
| 伍、討論 | 依結果解釋現象、比較組別與文獻，說明誤差、干擾及限制；無結果時僅保留待分析問題或明確的討論提綱。不得將因果、降雨預測能力或普遍可靠性寫得超過證據。 |
| 陸、結論 | 逐項回答研究目的，界定本次測試條件；未實測時標示待結果完成，與設計目標分開。不把目標成功率寫成已達成。 |
| 柒、參考文獻資料 | 正文引用與末尾書目雙向對應；作者、年份、題名、來源、DOI／URL等可追溯且格式一致。新增／更正文獻時查核第一手來源；沒查到就標示待確認，不能補造出版資料。 |

## 實驗追溯表

完整性報告每個子實驗至少列：目的、階段／編號、器材表位置、步驟位置、示意圖、可編輯紀錄表、結果／分析欄、討論／結論對應、狀態。檢查表格欄位足以記錄方法所需變項、試次數與時間；不能只數有幾張圖／幾個表就判定完整。

對植物成熟度、材料觸發或 Arduino 記錄等主題，額外檢查：分級標準是否由學生實際觀察建立；感測／記錄與驅動機構是否說明一致；遇雨通知與天氣預報的能力是否區分；門檻、精度與成功率是規格、預定標準還是實測結果。這些僅在相關研究出現時套用，不自動擴充研究內容。

## 格式與跨章一致性

- 依原檔樣式檢查字型、段落、大標題、子標題、頁面尺寸、邊界與分節；避免直接重建整份文件導致格式流失。
- 階段數、子實驗數與編號以最新已接受設計為準，不固定要求 4 階段、18 圖或特定頁數。
- 所有圖片內文字也納入前後一致性檢查。圖號、表號、正文指引、設備標註、樣本量與單位須相符；不只搜尋段落文字。
- 圖文直接整合於作品書，圖片不壓扁、不裁字；原生表格可輸入並可儲存重開。渲染僅供驗證，不把 PDF 當作可編輯觀察表交付。
- 保留學生原有的有效觀察與結果、分工註記及已確認內容；重新排版或整合不能抹去共同編輯內容。
- 報告列出檢查來源版本、每章狀態、發現與修正、待實測／待資料、渲染驗證範圍，以及是否實際更新共編檔。
